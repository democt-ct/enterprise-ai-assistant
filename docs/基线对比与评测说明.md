# 基线对比与评测说明

## 对比对象

- **Baseline**：领域 Router 选择多个专家，分别生成自然语言回答，最终直接拼接。
- **Current**：Router 仅提供候选领域；Case Manager 生成受限任务图，Case Runtime 管理状态，专家交换 Artifact，写操作经过 Resource Gateway 与审批网关。

## 架构能力对比

| 场景 | Router + 文本拼接 | 当前 Case 协作架构 | 验证方式 |
| --- | --- | --- | --- |
| 跨领域请求 | 多段回答，无任务状态 | 运行时任务图 + Artifact | 协作策略评测 |
| 专家读取其他领域资源 | 依赖 Prompt 约束 | Resource Gateway 默认拒绝 | `test_resource_gateway.py` |
| 专家请求写操作 | 可能直接调用工具 | 只返回 Operation Proposal | Resource Gateway 测试 |
| 用户未确认就执行 | 无统一保证 | 提案状态机拒绝执行 | Case 安全评测 |
| 单个专家失败 | 整次请求报错 | 持久化 Case 进入 `blocked` | Case Runtime 测试 |
| 敏感专家产物 | 容易广播完整上下文 | `private` Artifact 不进入共享上下文 | Case 安全评测 |
| 跨轮次恢复 | 请求结束后状态丢失 | Case/Task/Proposal/Event 持久化 | API E2E |

这张表是架构能力对比，不是线上效果实验。当前仓库没有真实用户流量，因此不提供未经验证的成本下降、处理效率提升或生产成功率指标。

## 当前评测口径

1. 主路由离线样本：20 条中命中 19 条，95%。
2. 协作策略回归：4/4，覆盖知识问答、并行研判、跨域写安全降级和确定性工作流。
3. Case 与安全边界：7/7，覆盖提案生成、确认/审批、任务收敛、隐私和资源越权。
4. API E2E：使用临时 SQLite 验证员工与 HR 两种角色的完整入职 Case 链路。

后续若扩展为实验性对比，应增加统一问题集，并评价答案完整性、证据覆盖率、越权率、Case 完成率和失败恢复率。
